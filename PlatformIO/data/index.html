Gauges (swipe order)

Tap a gauge to change it; its switch shows or hides it on the glass, and Move Up / Move Down change the order. Swipe left / right on the screen between the gauges switched on. Pick a source, then the value from it: Car lists everything Scan My Car found (its own tab); a second value (Dual, Haldex) comes from the same source. Drag Timer

On the screen: menu > Drag Timer. Tap to start: a 5 second countdown, then the flag drops (or the clock starts the moment the car moves). It stops at 100 km/h, or 60 mph when Speed is set to mph. Tap to cancel, double-tap for the scores. The best 10 times of each kind are kept here.

No CAN wire needed: the OpenHaldex sends its state over WiFi. Commands need its WiFi password and "Allow Gauges to Change Settings" on. Both must be on the same WiFi channel.

ADC - adc2can sensor expander

Eight 0-5 V sensors per adc2can board; the sensors of a board show once it's heard. Sensor settings live on the adc2can: edit them below (over CAN) and every gauge uses them. Over WiFi the sensors show without a CAN wire, but settings can only be changed over CAN.

usb2ip (ECU over WiFi)

--
Everyday values
--
usb2ip sends an Ignitron, MaxxECU, Link, Haltech or EMU PRO's data over WiFi. Everyday values fill in when nothing else provides them; every ECU channel can go on a gauge (Source = ECU). Same WiFi channel needed.

Set points

Signal lists only what this gauge has: the car's values, a gauge page's own values (Page values: whatever a page reads from a DBC, K-line, OBD, ECU, Diagnostics or ME7, set up on the Gauges tab), and the adc2can, usb2ip and OpenHaldex values once they've been heard. A trigger keeps its value read even when its page isn't showing or is switched off. K-line talks to one module at a time: when the pages and triggers use more than one module, a trigger's K-line value is only read while a page from the same module is on screen.
Hold = how long it must last. Hysteresis = how far back before it re-arms. Latch = stays on until the glass is tapped (or Clear Alerts); tapping an alert away keeps it quiet until its value is back past the threshold. No Reading = what to do when the value has none (a sensor unplugged, shorted or faulted, the bus gone quiet): Ignore waits, Trigger counts it as the condition met (from 5 s after power-on).

CAN bus

Termination: a CAN bus needs a 120R resistor at each end. In a car the car's wiring has them, so leave it Auto or Off. Auto listens at power-up: any CAN frame heard means the bus is terminated already and it stays off; nothing heard (gauges on their own, on the bench) and the first gauge to give up listening switches its 120R on, so the others hear a live bus and leave theirs off. If car frames turn up later it goes off again. On: always, for the last gauge on a chain with nothing else terminating it.
MaxxECU: in MTune turn on CAN output "MaxxECU Default 1.3" at this bit rate. Base ID 520 unless MTune's CAN ID offset moves it.
Relayed frames: an OpenHaldex or adc2can can pass the car's CAN to this gauge over WiFi.

ME7 logger

Logging: --
Tick a variable to log it, untick to drop it (up to 32). The list is saved to the .cfg and the logged variables show in the gauge-page sources.
For protocol "ME7 logger". Upload the .ecu (from ME7Info) and .cfg under Files below. The baud comes from the .ecu (LogSpeed). Samples/s is the most it asks for: an ME7 answers one request every ~10 ms, each holding 3 stretches of memory - variables next to each other share one - so the example's 11 variables take 3 requests (~34/s) and 6 or so neighbouring ones reach 50/s.

Gearbox source

Selector and gear come from the CAN profile's broadcast; the diagnostic read adds the gearbox's own speed. Picking a gearbox type fills in the reads below for it (change any of them after). On a BMW the gearbox only answers through the Bluetooth adapter or on the OBD port's CAN (D-CAN), with its address in front of every frame.
UDS (CAN or ELM)
The temperature is read every 10th pass. Lock-up comes out as 0 open, 1 slipping, 2 locked; the selector as the gauge's 1 P, 2 R, 3 N, 4 D, 5 S, 6 M. "Gearbox type's table" turns the gearbox's own codes into those (BMW DA22 / DA2E). The raw numbers show under Lock-up above, for working out another gearbox's codes.
TP2.0 (PQ35)
Defaults from a Mk5 DQ250 (02E300050H): block 1, field 4 (divisor 0 = use the formula byte). Check the live fields above for another gearbox.

Diagnostics (live)

--

Module

Up to 32 measuring values, any make, each from its own module (Scan My Car and the DID Library set that; a value typed in here reads the module above): UDS on MQB-era modules, KWP2000 blocks on PQ-era. Only the values a gauge page or trigger uses are asked for (all of them while this tab is open). Requests When used: while a gauge page shows a diagnostics value or this tab is open; Always: whenever the ignition is on. Turbo asks back to back and groups UDS values. If no module answers 3 times (once when nothing else is heard on the CAN) the tab stops asking until Restart Session, a settings change or the next ignition on.
The ids can be 11-bit (7E0) or 29-bit (17FC0076, 18DA01F1). Through the OBD adapter (Bluetooth / WiFi) the tab speaks UDS only, on CAN cars only and Turbo groups at most 3 values; the adapter carries on with its OBD values in between. Extended addressing is for BMW (EGS: out 18, back F1); leave it at 0 on everything else.

Values

UDS: DID, the first bit in the DID's data (byte 2 = bit 16) and how many bits, value = raw x scale + offset. Byte Order Low first is for values sent least significant byte first. KWP: block and field. Put one on a gauge with Source = Diagnostics, or add one from the DID Library above.

Try a DID

F187 part number, F189 software, F197 module name; F400 + an OBD PID (F40C rpm) on most modules.

Fault codes

Ignition on. From the gauge's own K-line or CAN, or through the OBD adapter. K-line tries KWP1281 (Mk4 era), then KWP2000; CAN tries UDS (MQB era), then TP2.0 (PQ era); the adapter speaks UDS (MQB era). Fault numbers as the workshop tools show them.

Scan Modules

Asks every module the gauge knows the UDS ids of (and the 29-bit engine / gearbox ids) for its part number, name and how many faults it has stored, Only reads. MQB-era modules only: PQ-era ones speak TP2.0. Tap a module to read its faults.

Throttle body adaptation

Runs the group in basic setting mode over the K-line (KWP1281 modules): the ECU learns the throttle's end stops itself. Do it after cleaning or swapping the throttle body. Field 4 is the result (ADP. OK when it worked); its raw bytes show next to it.
Ignition on, engine off, foot off the pedal. It stops by itself after 60 s, if the engine starts or if this page closes. Turn the key off for 10 s afterwards.

OBD adapter (ELM327 - Bluetooth or WiFi)

Saved adapter: --
Usually 192.168.0.10 port 35000. Joining moves the gauge's WiFi to the adapter's channel: your phone drops for a few seconds and reconnects.
CAN broadcast monitors the car's frames through the adapter and decodes them with the CAN tab's profile or DBC, for cars that broadcast on CAN but answer no OBD-on-CAN. K-line blocks through the adapter are set on the K-line tab.
Bluetooth LE ("iPhone compatible") adapters only, e.g. OBDLink CX, Veepeak BLE, vLinker MC+, Vgate iCar Pro BLE.

Daisy Chain

One master does the asking (OBD, gearbox, adapter, OpenHaldex modes) and every gauge shares its values. Every gauge needs the same group. Each gauge's role and number are set below, from any gauge.

Gauge Numbers

--
Every gauge on the link, this one included. The number is the gauge's place in the row, counted from the left as you sit in the car (1 = leftmost). Show Numbers puts each gauge's number big on its own glass for 15 s, and a gauge whose number or role is changed here shows its new one for a few seconds, so you can see which is which. Only one gauge can be set to Master; Auto lets the gauges choose.

At ignition off the gauges in a row wave to each other, then to you. Each gauge needs a number (above), an ignition source, the same off delay and a shutdown sprite with row clips (Rev). Play It Now plays it on every numbered gauge that has a shutdown sprite.

Menu and Tabs

What this car has: each switch shows or hides the gauge menu entry, its tab and its Dashboard tile. First Boot sets these for you.

Display

Night brightness is used while the illumination input is on. Make colours approximate each make's night lighting. "Match car" picks one from the VIN (OBD adapter).
Imperial is mph, psi, °F and miles (lambda stays lambda). Custom picks each one. The dials follow the units: a gauge's Min, Max and Redline are turned over to the new unit and rounded (280 km/h becomes 175 mph). Logs and triggers keep the gauge's own units (km/h, bar, °C).
Analog: needles glide like a real pointer. Digital: every reading shows the moment it arrives.

Screen Rotation

Turns the whole picture round the middle of the glass: Upside Down for a gauge fitted the other way up, Rotation Trim to straighten one that sits slightly crooked in its pod (+ turns it clockwise). Touch follows the picture. While either is set, each frame costs a little more to draw.

Ignition (permanent power)

For a gauge on permanent 12 V: at ignition off it plays the shutdown sprite and goes quiet, then deep-sleeps after the delay. Custom bit = byte x 8 + bit. In a chain only one gauge needs the CAN or wire ignition: set it on that gauge's own page and every other gauge switches to Another gauge and sleeps and wakes with it. The last gauge given an ignition wins (deep sleep needs the chain on CAN; on WiFi only they stay dark in standby). Off Delay, Deep Sleep After and the shutdown sprite are the same on every gauge in the chain.
